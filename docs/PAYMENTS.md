# Payments — status and plan (25.10.2026)

**Одна строка:** USDC-инвойс работает; карточный платёж **не работает**; Stripe/ENOT не настроены. Без карточного пути человек не может заплатить.

---

## 1. Что работает сейчас

### USDC на Base / Solana

1. Клиент получает подписанный JSON-инвойс (`docs/INVOICE-USDC.md`).
2. Платит USDC на адрес **из инвойса** (никогда из чата).
3. Присылает tx hash.
4. Мы проверяем перевод в блокчейне и выдаём квитанцию.

**Ограничение:** подходит крипто-клиенту с кошельком. Не подходит CFO/финдиру без кошелька.

### Бесплатный браузерный аудит

`https://mrpkk.github.io/nidhipati/free-spend-audit.html` — без аккаунта, без загрузки, <1 секунды на синтетическом примере. Это не платёж, но это вход в воронку.

## 3. Вариант A — Stripe Payment Link (если есть non-RF аккаунт)

Плюс: не нужен сервер, статическая страница может вести на готовую ссылку.  
Минус: нужен non-RF аккаунт; РФ-регистрация с выдуманной страной запрещена.

**Шаги владельца:**

1. https://dashboard.stripe.com/payment-links
2. Создать два one-time продукта: $2,500 и $1,250 (первые 3).
3. Скопировать ссылки.
4. Скопировать шаблон `/home/iamthat/.config/nidhipati/env.example` в `/home/iamthat/.config/nidhipati/env` и заполнить:

```
NIDHIPATI_STRIPE_AUDIT_URL=...
NIDHIPATI_STRIPE_FIRST3_URL=...
```

5. Агент добавляет ссылки на `/pricing` и проверяет переход.

**Что нужно от агента после ссылок:** обновить `pricing.html`, `index.html`, `OFFER.md`; проверить, что ссылки открываются; не хранить секреты в git.

## 4. Вариант B — ENOT (карты/СБП, реалистичнее для РФ/Индии)

В attest уже есть `attest/enot.py`: создание счёта, подпись уведомления, проверка статуса. Его можно адаптировать.

**Шаги владельца:**

1. https://enot.io/ — мерчант-кабинет.
2. Получить `ENOT_SHOP_ID`, `ENOT_API_KEY`, `ENOT_SECRET`, `ENOT_USDT_TRC20`.
3. Скопировать шаблон `/home/iamthat/.config/nidhipati/env.example` в `/home/iamthat/.config/nidhipati/env` и заполнить (не в git).
4. Агент адаптирует код, добавит `/pay` и `/pay/enot/notify`, прогонит тесты.

**Что должен сделать код:**

- создать счёт на $2,500 / $1,250;
- проверить подпись уведомления;
- проверить сумму/статус/идентификатор заказа;
- выдать доступ/начать аудит только после `paid`;
- не хранить карточные данные;
- refund по гарантии — вручную, тем же способом.

**Чего не делать:** не принимать карточные данные на своём сервере; не хранить `ENOT_SECRET` в репозитории; не выдавать аудит до подтверждения оплаты.

---

## 5. Гарантия и возврат

Оффер: если аудит не найдёт **$5,000** документированных переплат/возможностей возврата за 10 рабочих дней — возврат гонорара.

- «Документировано» = строка + чек/инвойс или tx hash + письменное основание.
- Гарантия про **найденные суммы**, не про фактический возврат от провайдера.
- Возврат — в том же активе/сети, минус сетевые комиссии.
- Условия должны быть в письменном соглашении до оплаты.
